# 9~10차시 새 구성

## 기획: 주제는 열어 두고, 성공 기준은 정해 준다

> 오늘의 과제: 내 아이디어 카드를 **옆 사람이 써도 움직이는** 작품으로 만든다.

1. **무엇을 만들지는 묻지 않습니다.** 7~8차시 카드(불편을 줄이는 작품이든, 보여 주고 싶은 작품이든)를 그대로 씁니다.
2. **움직임과 코드는 각자 정합니다.** 카드에는 서보 두 개가 할 일을 말로만 적고, 각도·횟수·멈춤은 만들면서 정합니다.
3. **성공은 시험으로 정합니다.** 옆 사람이 설명 없이 5번 해서 4번 이상 움직여야 합니다. 틀린 모양에 따라 고칠 곳(AI 인식 · 코드 · 구조)을 찾습니다.
4. **수업 적용은 방금 한 과제의 해설입니다.** 정해 준 것 · 열어 둔 것 · 시험한 것, 이 세 칸으로 우리 반 과제를 짭니다.

## AI 모델: 모션인식 대신 음성인식

- 카드에서 고르는 모델이 **핸드포즈 · 이미지분류 · 음성인식**입니다(`challenges.js`의 `MK.cardModels`).
- 음성인식 웹앱: `https://boundary-x.github.io/voice_recogntion_ondevice/`. 웹앱의 **명령어 추가**에서 "새 명령어 = 내가 정한 말, 영어 데이터 = ID1(또는 ID2)"로 적으면 **7차시 기본 코드를 그대로** 씁니다. 웹앱은 `데이터 + 줄바꿈`을 보내고, 기본 코드는 줄바꿈까지 읽어 ID1·ID2와 비교합니다.
- 그래서 세 모델 모두 같은 코드입니다. 「나의 모델 코드 확인하기」 쪽에서 모션인식 예제 코드를 빼고 음성인식 웹앱 바로가기를 넣었습니다. 음성인식은 7~8차시에서 다루므로 「음성인식으로 하려면」 쪽은 다시 보기용으로 자료 묶음에 두었습니다.
- **서버도 함께 바꿔야 합니다.** `backend/Code.gs`의 `CARD_MODELS`에 `'음성인식'`을 넣어 두었습니다. Apps Script에 다시 붙여 넣고 새 버전으로 배포하기 전에는 음성인식 카드가 등록되지 않습니다.
- 실제 마이크로비트로는 시험하지 못했습니다. 특히 "한 번 말하면 한 번만 보내고, 기본 코드는 다른 글자가 올 때까지 같은 움직임을 되풀이한다"는 것은 코드 화면과 웹앱 설명을 읽고 판단한 것입니다.

## 저장 방식

- `config.js`의 `apiUrl`에 구글 시트 Apps Script 웹 앱 주소가 있으면 **온라인 모드**입니다.
  - 도전과제 등록·제출이 모든 화면에 몇 초 안에 공유됩니다.
  - 기록은 구글 시트의 `설정 / 신청 / 제출 / 도움 / 하트 / 아이디어 / 카드 / 편집 / 메모` 탭에 쌓입니다. (`카드` = 내 도전과제, `신청` = 예전 방식 기록)
  - 정원과 관리자 비밀번호는 서버에서 확인합니다.
  - **여러 사람이 한꺼번에 저장할 때**: 서버는 저장을 한 줄로 세워 1초에 1건쯤 처리합니다. 서버가 '잠시 밀렸어요'라고 하면 교안이 1.5·3.5·6·10초 뒤에 알아서 다시 보냅니다(같은 결과가 나오는 요청만). 읽기가 한 번 실패한 것만으로는 '서버 연결 끊김'을 띄우지 않고, 두 번 잇달아 실패하면 띄웁니다.
- `apiUrl`이 비어 있으면 **데모 모드**입니다. 기록이 각자의 브라우저에만 남습니다.
- 서버 설치 방법은 프로젝트 폴더의 `backend/설치 안내.md`에 있습니다(이 저장소에는 올리지 않습니다).

### 슬라이드 추가

교안 파일(`deck-7-8.html`, `deck-9-10.html`)에서 모양이 비슷한 슬라이드 하나를 통째로 복사해 원하는 위치에 붙이고, `id`와 글자를 바꿉니다.

- 배경 4가지: `slide--cover`(표지) · `slide--body`(본문) · `slide--pixel`(섹션 구분) · `slide--pastel`(발표회)
- `data-section`: 목차에서 묶일 이름
- `data-title`: 목차에 보일 제목
- 쪽 번호와 꼬리말은 자동으로 붙습니다.

작품 발표회 슬라이드는 제출물로 **자동 생성**됩니다. HTML에서는 `<div data-generate="showcase">` 자리만 있습니다. 도전과제 예시 7가지(PART 5 맨 뒤 「덤」, 원래 오늘 하려다 접은 과제)는 `challenges.js`로 그려지고, 누르면 자세한 창(교과와 잇기 포함)이 열립니다.

**PART 5 · 수업으로 가져간다면** (방금 겪은 수업의 해설): 화면에 띄울 세 쪽 = 방금 한 수업의 뼈대 → 난이도는 조건으로 조절합니다(조건은 정하고, 해결은 열어 둔다) → 세 가지 출발점(틀만 / 엔트리 5~6학년 / 영재학급·동아리). 그 뒤 「가져가실 자료」 쪽에서 누르면 이동: 강사의 생각 · 쓰기→바꾸기→만들기 · 다섯 갈래 · 바이브코딩 · 재료 · 운영 팁 · 덤(도전과제 예시 7가지) · 발표회 다시 보기.
- 작품 장르는 **문제 해결 작품 / 표현·놀이 작품** 둘 다 됩니다. 「내 도전과제 등록」에서 고르면 ‘누가 겪는 불편’ 칸이 빠집니다(서버 수정 없음).
- 발표회 표지와 작품마다 "끝에 한 문장 · 학생과 한다면 바꿀 조건 하나"가 보입니다.

## 화면에서 바로 글자 고치기 (편집 모드)

1. 교안에서 관리자로 들어갑니다 (`Ctrl+Shift+A`).
2. 오른쪽 위 **편집** 버튼을 누르거나 `Ctrl+Shift+E`를 누릅니다.
3. 점선이 생기는 글자를 눌러 고칩니다. Enter(또는 Shift+Enter)는 줄바꿈, Esc는 끝입니다.
   - 도전과제 제목·질문, 공통 조건 한 줄, 표지의 연수 정보는 한 줄짜리 칸이라 Enter를 누르면 고치기가 끝납니다.
4. **저장**을 누르거나 `Ctrl+S`를 누릅니다.
   - 크롬·엣지에서는 처음 한 번 `site` 폴더를 고르면, 그 안의 파일을 직접 고칩니다.
   - 사파리 같은 다른 브라우저에서는 고친 파일을 내려받습니다. 같은 이름 파일과 바꿔 넣으면 됩니다.

고친 내용이 저장되는 곳:
- 슬라이드 글자 → 지금 연 교안 파일(`deck-7-8.html` 또는 `deck-9-10.html`)
- 도전과제 설명·공통 조건 → `assets/js/challenges.js`
- 표지의 연수 정보 → `assets/js/config.js`

교안을 열고 처음 저장할 때, 고치기 전 파일을 `site/_backup/날짜-시각/`에 남깁니다. 같은 창에서 이어서 저장할 때는 새로 남기지 않습니다. 필요 없으면 지워도 됩니다.
그림, 배치, 슬라이드 추가·삭제는 편집 모드로 할 수 없으니 파일에서 고칩니다.

## 다른 사람이 웹 주소에서 고치고 보내기 (편집·메모)

소스 파일이 없는 사람(예: 7~8차시 강사)도 웹 주소만으로 교안을 고쳐 보낼 수 있습니다. 서버 새 버전(`backend/설치 안내.md`의 2026-11-12 항목)이 필요합니다.

**고치는 사람 (웹 주소에서)**
1. 교안 웹 주소를 열고 `Ctrl+Shift+A`(맥도 control) → **편집자 비밀번호**(`Code.gs`의 `EDITOR_PASSWORD`).
   - 편집자는 글자 고쳐 보내기·메모만 됩니다. 반영과 연수 관리 기능은 서버가 막습니다.
2. `Ctrl+Shift+E`(또는 관리자 › 교안 편집 › 켜기)로 편집 모드를 켜고 글자를 고칩니다.
3. 위쪽 막대의 **보내기**(또는 `Ctrl+S`, 맥은 `⌘S`). 처음 한 번 이름을 묻습니다.
   - 같은 곳을 다시 고쳐 보내면 하나로 합쳐집니다. 원래대로 되돌려 보내면 빠집니다.
4. 글자로 못 고치는 것(사진, 순서, 배치 등)은 오른쪽 위 **메모** 버튼으로 그 쪽에 남깁니다.

**교안 담당자 (반영하는 기기 = site 폴더가 있는 내 컴퓨터)**
1. 내 컴퓨터의 `deck-7-8.html`을 크롬으로 열고 관리자로 들어갑니다. (웹 주소에서 하려면 관리자 › 편집·메모 탭 맨 아래 **이 기기에서 반영하기**를 한 번 누릅니다)
   - 받은 편집이 있으면 오른쪽 위 **메모** 버튼 옆에 「받은 편집 N」이 보이고, 아래 막대에 점이 찍힙니다.
2. 관리자 › **편집·메모** 탭에서 원래 글자(빨강)와 고친 글자(초록)를 확인하고 **모두 내 파일에 반영**을 누릅니다.
   - 받은 편집을 넣고 site 폴더의 파일에 바로 저장합니다(처음 한 번 site 폴더를 고름).
   - **파일 저장에 성공한 것만** 목록에서 빠집니다. 넣고 싶지 않은 것은 먼저 **반영 안 함**.
   - 그사이 같은 자리를 내가 먼저 고쳤으면 덮어쓰지 않고 알려 줍니다(**그래도 넣기**).
3. `배포하기.command`를 누르면 웹 교안에 올라갑니다.
4. 메모는 처리한 뒤 **완료**를 누릅니다.

- **글로 정리해 보기**: 받은 편집과 메모를 쪽 순서로 정리한 글. 복사해 두거나 메신저로 보낼 수 있습니다.
- **처리한 편집 → 다시 받기**: 잘못 빼거나 취소한 편집을 되살립니다(최근 40개).
- 반영은 **관리자 비밀번호**로 들어온 사람만 할 수 있습니다(서버가 확인). 편집자는 보낸 편집을 확인하거나 **내가 보낸 것 취소**만 할 수 있습니다.
- 메모와 받은 편집은 관리자에게만 보입니다. 연수생 화면에는 아무것도 나오지 않습니다.
- 받아 오는 내용은 구글 시트의 `편집`(상태: 대기·반영·버림), `메모` 탭에 있습니다. 코드는 `assets/js/review.js`.

- **발표자료**: 발표 슬라이드로 이동하기, 발표 순서 뽑기(무작위), 작품별 하트 수. "발표 파일 저장"은 발표 슬라이드만 HTML 파일 하나로 저장합니다(현장 인터넷 대비용. 영상 재생은 인터넷 필요).
- **데이터**: JSON·CSV(엑셀) 내보내기, JSON 가져오기, 샘플 6개 넣기·지우기, 전체 초기화

관리자로 들어가면 우리 반 도전과제 보드에서 카드를 눌러 숨기기·지우기를 할 수 있습니다. 타이머 쪽에는 시작·멈춤·+5분·처음으로 버튼이 보이고(연수생 화면에는 없음), 아이디어 벽의 모든 카드에 지우기(×)가 보입니다.

연수생 본인 확인은 이름과 숫자 4자리 비밀번호로 합니다. 비밀번호는 내 도전과제나 결과물을 고칠 때만 씁니다.

## 인터넷에 다시 올리기 (배포)

`site` 폴더에서 고친 뒤, 프로젝트 폴더의 **`배포하기.command`**를 더블클릭합니다. 1~2분 뒤 인터넷 주소에 반영됩니다.

- 공개본에는 `config.js`의 데모 비밀번호를 비워서 올립니다.
